FinDesk – Modern Moneyplex Successor

A Kotlin JVM + Compose Desktop + HBCI4Java based local banking & document workspace.

1. Product Identity & Positioning

1.1 Name & Core Idea

Product name: FinDesk

Concept: A personal financial workspace that unifies multi-banking, transactions, documents and tax-relevant information in a secure local desktop application.

1.2 Brand Attributes

  • Target: Power users, self-employed, small businesses, privacy-conscious users.
  • Tone: Professional, modern, trustworthy, technical.
  • USP: Local-only data, multi-bank FinTS/HBCI, document & OCR integration, modern UI.

1.3 Visual Identity

  • Logo concept: Desk-like icon with an upward arrow (finance trend) next to the word “FinDesk”.
  • Colors: Primary blue (#2D6CDF), teal (#3BC7B0), dark gray (#2F2F2F), light background (#F5F7FA).
  • Typography: Modern sans-serif (e.g. Inter, Poppins, Source Sans Pro).
  • Slogan examples: “Your Financial Workspace.” / “Finances. Clear. Local.”

2. High-Level Architecture

2.1 Stack

  • Language: Kotlin JVM
  • UI: Compose Desktop (Compose Multiplatform JVM target)
  • Banking engine: HBCI4Java (FinTS/HBCI)
  • Database: SQLite (optionally SQLCipher for encryption)
  • OCR: Tesseract via JNI or external process

2.2 Layered Architecture

UI Layer (Compose Desktop)
  - Dashboard
  - Accounts
  - Transactions
  - Payments
  - Documents
  - Reports / Tax

Application / Domain Layer
  - AccountService
  - TransactionService
  - PaymentService
  - CategoryEngine
  - DocumentService
  - RuleEngine

Banking Integration Layer (HBCI4Java)
  - FinTSClient
  - FinTSJobFactory
  - TANManager
  - BPD/UPD Cache

Persistence Layer
  - SQLite / SQLCipher
  - Repositories (Exposed/JOOQ)
  - Local encrypted storage

System Services
  - OCR Engine (Tesseract)
  - PDF parsing
  - File storage
  - Logging & Audit
  - Plugin loader

2.3 Data Flow (Example)

User Action (e.g. open account overview)
  ▼
Compose UI (AccountsView)
  ▼
AccountService
  ▼
Repositories (SQLite)
  ▼
UI state updated (Compose state)
    
User Action (SEPA payment)
  ▼
PaymentView (Compose)
  ▼
PaymentService
  ▼
FinTSJobFactory + HBCI4Java
  ▼
Bank server (FinTS)
  ▼
Result → TransactionService → DB → UI

3. UI Structure & Screens (Compose Desktop)

3.1 Global Navigation

  • Sidebar entries: Dashboard, Accounts, Transactions, Payments, Documents, Reports/Tax, Settings.
  • Top bar: App logo, active bank profile, sync status, theme toggle.

3.2 Key Screens

Dashboard

  • Widgets: Current balance, incoming, expenses, pending tasks.
  • Recent transactions: Table with last few entries.
  • Charts: Expense overview (pie), tax deductions (bar).

Accounts Overview

  • List: Checking, savings, credit card, etc. with balances.
  • Balance history: Line chart per account.
  • Upcoming payments: Bills, subscriptions, insurance with “Schedule transfer” button.

Transactions & Receipts

  • Filters: Date range, account, category, amount, text search.
  • Transaction list: Date, amount, partner, purpose, category.
  • Details panel: Selected transaction with attached receipts, notes, tax relevance.

Tax Report & Documents

  • Tax summary: Annual income, deductions by category.
  • Document manager: List of PDFs/images linked to transactions or categories.
  • Actions: Add document, link/unlink, open, search by OCR text.

4. Data Model Overview

4.1 Modules & Tables

Module Main Tables Purpose
Banking bank_access, accounts, transactions, tan_sessions FinTS/HBCI integration, accounts & transactions
Documents documents, ocr_texts, document_links (optional) Receipt/document storage, OCR, linking to transactions
Categorization categories, rules Automatic classification & budgeting
System settings, plugins, audit_log Configuration, extensibility, security logging

4.2 Banking Tables

bank_access

  • id: INTEGER PK
  • bank_name: TEXT
  • blz: TEXT
  • bic: TEXT
  • user_id: TEXT
  • hbci_version: TEXT
  • tan_method: TEXT
  • last_sync: DATETIME

accounts

  • id: INTEGER PK
  • bank_access_id: INTEGER FK → bank_access
  • iban: TEXT
  • account_number: TEXT
  • balance: DECIMAL
  • currency: TEXT
  • account_type: TEXT (checking, savings, credit card, etc.)
  • last_update: DATETIME

transactions

  • id: INTEGER PK
  • account_id: INTEGER FK → accounts
  • date: DATE
  • amount: DECIMAL
  • currency: TEXT
  • partner_name: TEXT
  • purpose: TEXT
  • category_id: INTEGER FK → categories
  • document_id: INTEGER FK → documents
  • hash: TEXT (for duplicate detection)
  • created_at: DATETIME

4.3 Document Tables

documents

  • id: INTEGER PK
  • file_name: TEXT
  • file_path: TEXT
  • mime_type: TEXT
  • upload_date: DATETIME
  • ocr_text_id: INTEGER FK → ocr_texts
  • linked_transaction_id: INTEGER FK → transactions

ocr_texts

  • id: INTEGER PK
  • document_id: INTEGER FK → documents
  • content: TEXT
  • language: TEXT
  • confidence: DECIMAL

4.4 Categorization Tables

categories

  • id: INTEGER PK
  • name: TEXT
  • color: TEXT
  • budget_limit: DECIMAL
  • is_tax_relevant: BOOLEAN

rules

  • id: INTEGER PK
  • pattern: TEXT (regex or simple text match)
  • category_id: INTEGER FK → categories
  • priority: INTEGER
  • auto_apply: BOOLEAN

4.5 System Tables

settings

  • id: INTEGER PK
  • key: TEXT
  • value: TEXT
  • updated_at: DATETIME

plugins

  • id: INTEGER PK
  • name: TEXT
  • version: TEXT
  • enabled: BOOLEAN
  • entry_point: TEXT (class name or path)

audit_log

  • id: INTEGER PK
  • timestamp: DATETIME
  • action: TEXT
  • user: TEXT
  • details: TEXT

5. Entity Relationships (ER Summary)

BankAccess 1 ── ∞ Accounts
Accounts   1 ── ∞ Transactions
Transactions ∞ ── 1 Categories
Transactions 0..1 ── 0..1 Documents
Documents   1 ── 1 OCR_Texts
Categories  1 ── ∞ Rules

Central entities are Accounts and Transactions, with Documents and Categories enriching them for receipts and classification.
